# 03: Publish the Manuscript Template and reject unedited Manuscripts

**What to build:** KMSC receives one Word document showing exactly how to lay out a Manuscript, downloadable from the import control in the editor. A Manuscript that still contains the template's placeholder text is rejected rather than turned into a Blog Post.

**Blocked by:** 02 — Start a Blog Post from a Manuscript (title and body).

**Type:** task

**Status:** resolved

Spec: Manuscript Import specification; ADR-0002.

- [x] The Manuscript Template contains example text in the Title, Heading 1, Heading 2, Normal, bulleted-list and numbered-list styles, and a Tags (keywords) property, with no images.
- [x] Every instruction is a Word comment attached to the text it explains; no instruction appears in the document body.
- [x] The opening paragraph's example text explains that it becomes the summary and should be one or two sentences.
- [x] The template is committed with the site's static assets and linked as "Download the Manuscript Template" from the import control.
- [x] Importing the unedited template, or a Manuscript whose title or opening paragraph still matches template placeholder text, is rejected with a message explaining what to replace, and no form opens.
- [x] The importer's placeholder phrases and the template's placeholder text come from one shared definition, so they cannot drift apart.
- [x] A filled-in copy of the template becomes the base fixture for tickets 04 to 06 and imports successfully.
- [ ] The template opens without errors or compatibility warnings in Microsoft Word and LibreOffice. (LibreOffice: opens and converts to PDF; verbose debug logging shows the same warnings for any pandoc-made .docx. Microsoft Word: NOT verified; see Answer.)

## Answer

Implemented; one criterion remains open for a human check.

- **Template:** `public/admin/manuscript-template.docx`, linked as "Download the Manuscript Template" in the import control. Generated by `scripts/build-manuscript-template.mjs` (needs pandoc; maintainers only, not run in CI). Six Word comments carry every instruction; the Tags property holds a placeholder. The title uses the Title style, section headings Heading 1/2, and body text the Normal style.
- **One definition of placeholders:** `src/admin/manuscript-placeholders.js` feeds both the template generator and the importer. Rejection matches the plain text of the whole document (not the Markdown), so bold or italic inside a placeholder cannot hide it. The reason names the phrases to replace. The Tags placeholder is not checked yet: ticket 04 reads document properties and adds it (marked in code).
- **Fixture:** `tests/fixtures/manuscripts/template-filled.docx`, a finished example from the same generator, is the base for tickets 04 to 06.
- **Review changes:** placeholder matching moved from Markdown to plain text; body text now uses the Normal style; JSZip moved to devDependencies.
- **Open, needs a person:** open `manuscript-template.docx` in Microsoft Word and confirm there is no compatibility prompt, that the comments show in the margin, and that File > Info > Tags shows the placeholder. Regenerate with the script if Word objects.
